# Jev 离线研究初版 R1 · v0.6.0

本版交付的是可在当前电脑运行的通用任务初版：用户给出明确要求，Jev决策模块选择资料来源和已登记的模型/工具，程序执行、检查并保存阶段报告，缺资料时可补充后继续。当前离线实现为独立 **AnyJev + Qwen3-1.7B**，不是商用 Jev 权重，也不能作为商用 Jev 效果的证据。本轮按“先做出可用初版”推进，不开展有效性对照。

## 打开工作台

双击项目目录内的 `打开工作台.cmd`，等待启动检查后打开 <http://127.0.0.1:8765/>。确认页面显示 v0.6.0、本地服务已连接和离线状态。若未打开，查看 `logs/launcher.log` 与 `logs/server.stderr.log`，无需重新下载已有模型。

PowerShell 中也可启动或停止：

```powershell
cd 'D:\1 jev\jev-edge-prototype'
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\start.ps1
# 使用结束后停止服务
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\stop.ps1
```

旧版本后台服务仍在运行时，先停止再启动。推理期间不要并发运行第二份模型进程；首次加载模型通常更慢。

## 先用两条完整任务

在“任务工作台”选择“多步任务 · Jev协调”。每项要求单独占一行并编号，最多4项；不要在编号清单外另写任务，高级参数和验收 JSON 保持 `{}`。这类清单由用户拆分，不能记为模型自主规划。原文与CSV、示例及高级设置默认收起，按需展开即可。

展开“任务示例”，点击 **“分析CSV → 总结 → 统计”**，再运行。示例会附上 `workspace/inbox/r1-demo` 的两份 CSV，并展开附件配置，先生成数值报告，再总结报告并统计总结字符数。请求原文见 [examples/r1_dataset.json](examples/r1_dataset.json)。

点击 **“计算 → 补资料 → 继续”**，再运行。第一步计算 `(31-7)/3`，第二步因缺少待翻译原文而等待资料。保留计算结果后，在结果区“补充资料后继续”粘贴一段英文并继续。示例请求见 [examples/r1_continue.json](examples/r1_continue.json)。

也可以输入“总结原文 → 统计上一步总结结果的字符数”，展开“原文与CSV资料”粘贴原文。普通问答、单次工具和独立 CSV 模式仍保留。

## 使用自己的 CSV

1. 把文件放入项目的 `workspace/inbox/<资料目录>/`，不要填磁盘绝对路径。
2. 在多步任务模式展开“原文与CSV资料”，勾选“附加本机CSV资料”，填写相对资料目录、数值字段，可选状态字段和异常阈值。
3. “CSV文件顺序”可填 `before.csv, after.csv`；两份文件按该顺序作前后比较，留空则按文件名排序。阈值检查为**严格大于**，不是大于等于。

当前只读取1至2份 UTF-8 CSV（可带 BOM），每份不超过1MB、5000条数据、32列。表头必须唯一且非空。数值字段中的缺失或非法值会记录并排除出数值统计；不能把排除后的均值解释为全体记录的均值。全无有效数值时不能交付有效统计结果。报告中的行号是含表头的逻辑 CSV 记录编号，含换行字段时不等于文本物理行号。

CSV产出包含数值统计、可选状态计数、阈值结果、两份数据比较及源文件哈希。状态计数不代表回答正确率。附加模型建议默认关闭，开启后仍须核查。

传给后续模型的明细采用有上限的预览：列表最多50项，状态最多20项且受4KB限制，调用轨迹最多200项，省略数量单独标注。完整状态、命中行和数值结果保存在CSV成果中，不能根据预览推断完整明细。

## 查看成果、历史与续接

每次任务在结果区提供 Markdown 阶段报告和 JSON 完整记录；通用任务调用 CSV 后还会列出子任务的 CSV 成果链接。成果保存在 `workspace/runs/<运行编号>/`，任务历史保存在 `workspace/tasks/<任务编号>/`，日志在 `logs/`。下载前会核对交付时的文件哈希，文件被改变后拒绝下载。

侧栏“历史任务”可搜索、按状态筛选和重新打开保存的任务，服务重启后仍可查看。历史详情隐藏新建任务的运行表单，防止将续办误点成重新运行。可继续的任务显示补充区：补充原文，或勾选更新CSV并直接填写补充区内的附件配置，再点“继续此任务”。

点击“复制为新任务”可编辑新的要求；点击侧栏“任务工作台”返回查看历史前的草稿。草稿只在当前页面内临时保留，刷新页面不保留未提交内容。“新建任务”清空输入与旧结果。多步结果按项展示，“本次成果”集中提供下载，任务计划、决策过程和原始记录按需查看。

续办请求异常时，页面会先重读已保存阶段：阶段未变化则保留补充内容供重试，已有新阶段则展示最新成果；若无法确认最新状态，会暂时禁用继续，恢复连接后从历史重新打开任务再处理。

- 每个任务最多补充3次；已执行完计划的任务不能继续补充。
- 新资料只用于未完成步骤，已完成结果按原输入保留，不重复调用。
- 续接保留任务编号并产生新阶段和运行编号；不能在续接中修改目标或已完成结果。
- 如果需要修改前置事实、重算已完成步骤，或更换整个任务要求，请新建任务。

## 怎样理解状态

| 状态或字段 | 含义 |
|---|---|
| 待补充资料 `waiting_input` | 已保存阶段结果，缺少后续所需资料 |
| 已交付·待核查 `needs_review` | 已有输出或成果，但自然语言事实、信息完整性等仍需核查 |
| 声明条件通过 `completed` | 仅报告中声明的确定性工具条件通过，不覆盖额外要求 |
| 已停止 `stopped` | 达到预算、没有可用能力或发生无法继续的错误；查看原因和未完成要求 |
| `execution_complete` | 当前计划步骤已经执行并返回，不证明需求无遗漏或语义正确 |

通用任务不以模型自评宣称整体正确，`task_complete` 保持 false，语义准确率保持 null。工具选对、调用成功、有限检查通过、答案正确分别记录；有来源或来源哈希也不证明每句话有充分证据。未完成任务的可下载报告是阶段记录，不应当作最终完成证明。

## 环境、边界与验证

本阶段完全离线，不依赖远端服务。模型、环境、缓存和私人输入输出保持在 D 盘；现有 Qwen 与 BGE 权重直接复用。项目 `.venv` 依赖现有 `D:\Anaconda` 基础运行时，因此 Git 仓库不是可独立恢复整台机器环境的镜像。

当前仍是受限工具框架：单段目标自动拆分和一次重规划属于试验能力，可能漏项或失败；摘要、翻译、改写和模型建议仍可能遗漏或补造信息，需人工复核。没有真实设备控制、邮件发送、实时联网查询、任意代码执行或任意文件修改能力；任务最长300秒，单次模型调用最多120秒，超限会停止。目标设备迁移及遥感、养老场景验证留到后续。

本轮真实输入、输出、失败、耗时和资源数据见 [v0.6.0 推进与验证记录](reports/progress-20261015-v060.md)，初版验收范围见 [RELEASE_CRITERIA.md](RELEASE_CRITERIA.md)。单元测试中的故障注入不算真实模型恢复效果，界面逻辑回放不算浏览器视觉验收；本轮不据测试数量宣称准确率。

复现检查时，先结束正在运行的任务。第一条会实际运行本地模型并重启本项目服务，随后从保存记录核对CSV数值；其余检查不需要第二份推理进程：

```powershell
cd 'D:\1 jev\jev-edge-prototype'
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\verify_release.ps1
.\.venv\Scripts\python.exe .\audit_release.py
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
node .\tests\ui_replay.cjs
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\tests\test_windows_launcher.ps1
```

验收记录采用唯一文件名保存在 `logs/`，最新本轮记录路径见 `logs/r1-verification.local.json`。这些问题是功能开发验收资料，不是独立最终测试集。报告示例见 [任务阶段报告](reports/r1-example-delivery.md) 与 [完整CSV报告](reports/r1-example-csv.md)，使用合成数据。

阶段成果由用户自行 Git 提交和推送；模型、环境、缓存、日志及私人任务文件不入 Git，历史记录保留，不额外复制完整项目备份。
