# 离线通用处理初版 · 0.3.1

## v0.3.1：任务契约与有限补救

- 双击项目内 `打开工作台.cmd`，脚本先启动并核对服务版本，再打开本地页面；也可运行 `start.ps1`。
- `task_contract.py` 从显式任务表述提取操作、材料要求、需要保留的字段状态及否定关系。这是有限程序规则，不是 AnyJev 独立判断。
- 未提供、未确定、未公布、未测量、未核查按字段区分。改写中的否定与同句数量关联检查，补充原有数字/时间/邮箱保护；检查可能误报或漏报，不能证明完整语义正确。
- 改写或写作草稿触发保护时最多重写一次。两次真实草稿、检查原因、耗时和 token 用量保留；仍失败则保留原文或拒交，不无限重试。`needs_review`本身不会触发重写。
- 高分停止与可用能力存在冲突时也可复核；整次请求最多一次路线复核，结果仍可停止。不存在可用能力时不会强制回答。
- 原始模型选择、复核、程序预检查、程序调整与实际执行分开记录。预检查停止没有原始模型选择，不应记为模型选对。
- 新开发数据 `evaluation_data/dev-v031.json`，新留出数据 `holdout-v031.json`，独立冻结 `release-v031.json`。旧 `release.json`、旧最终数据与所有模型评价保持原样；旧最终失败已为本轮设计提供信息，不能作为本轮独立测试。
- 本版仍不解决一般问答的通用事实核验、资料覆盖充分性和真正的语义压缩。通用结果继续待检查；完全离线，不更换模型。

运行对照：`./.venv/Scripts/python.exe run_iteration.py --profile contract`；规则对照使用 `--profile rules`。开发消融使用 `no-stop-review` 或 `no-preservation`。新版留出须另加 `--dataset evaluation_data/holdout-v031.json --freeze evaluation_data/release-v031.json`，仅复现冻结结果，不能据此调试本版。

本轮未更换或下载模型。`core.py` 入口会把模型库、Torch、临时文件缓存固定在D盘项目内，并启用离线环境。模型和历史记录审计见 `logs/project-audit-*.json`。

## v0.3.0 的质量与控制变化

- 资料问答选择完整本地原段落，由程序按编号核对和呈现；不再自由改写成新事实。对用户提供材料的资料问答也可选择原句证据。
- 总结采用完整原句摘录，并保留含否定、未测量、未验证等限制的原句；选择与程序保留分别记录。摘录可遗漏要点、冗长或不满足“一句话”形式，不能算自由归纳能力已解决。
- 改写、写作、信息提取检查新增数字、日期、邮箱、部分背景与否定信号。命中时保留原文或拒交草稿，保留草稿和原因供研究；这是有限词法保护，未命中不证明事实正确。
- 缺原文的文字变换明确请求材料；已给原文的变换误选停止时最多一次生成式能力复核。程序来源约束在复核之后执行，避免被复核覆盖。
- 字符串包含、精确文字、检索ID通过只记局部验收通过，不能记通用任务完成。`needs_review`包括已返回但未可靠验收的结果。
- 新评价分开发24条与冻结留出20条；原始选择、复核、程序调整、执行结果、语义标注分开。详见 `evaluation_data/PROTOCOL.md`。`run_probes.py` 另检查8条措辞变化与给定材料问答。

局限：任务种类识别仍有词法规则，非典型表述可能绕过质量保护；资料段落自身可能过期。当前质量保护收益属于程序与执行机制，不是AnyJev独立决策效果。

本版扩展通用问答与服务调用。下载后模型在本机运行，`offline_mode=true` 阻止远端调用。研究目标仍是决策、调用、验收与反馈，模型的回答能力需独立评估。

## 能处理的输入

- 在“问题或处理要求”直接输入问题；补充资料可以留空。
- 一般问答、解释、写作、总结、改写、翻译由本地 Qwen3-1.7B 处理。
- 关于 Jev、AnyJev 和项目的问题，可检索本地参考资料后生成回答，并显示被检索的来源。显示来源并不证明生成的每句话均被来源支持。
- 需要原始段落时可请求本地检索。
- 简单算式可从有限格式的自然语言中提取；程序校验后执行计算。复杂自然语言数学题仍可能由语言模型处理或请求补充信息。
- 字符统计由程序工具完成。
- 未登记的设备操作无法真正执行；没有实时数据接口，当前新闻、天气、股价等不能离线核实。

## 模型与控制

AnyJev + Qwen3-1.7B 负责候选概率读出；Qwen3-1.7B 也用于语言处理。二者共用权重，BGE 中文检索保留在 CPU。商用 Jev 与本地 AnyJev 的身份在配置和日志中区分；离线模式不调用商用 API。

候选分数低于临时集中度阈值时，最多进行一次生成式服务选择复核。复核只返回可用候选 ID 和原因，类型检查通过后执行；复核失败继续遵守原有低分阻断。复核单独记录，不篡改原始概率、不声称得到校准的正确率。高分的停止选择不强行改成回答。

检索问答由程序编排“检索 → 模型选择原段落 → 程序核对并呈现”。返回结果仍需验收；原句来源对应不代表回答充分。输出达到长度上限也标为待检查。资料库变化后会重新计算嵌入。

0.2.0 上限：总时间300秒，单次调用120秒，最多3个主步骤，生成最多512 token，输入提示最多4096 token。复核、模型加载与检索生成计入时间。

## 验证

运行 `./.venv/Scripts/python.exe evaluate.py --suite acceptance` 检查20个预定义请求。记录保存到 `logs/evaluations`；其中包括一般问答、改写、翻译、数学、检索、缺资料和不支持的操作。

评价记录分别统计路由匹配、声明验收通过，并保留每条输出供人工核查。字符串包含和检索 ID 匹配只检查局部条件。没有人工标注的语义正确率为 null。该小型回归集包含开发中用过的问题，不可用来报告泛化效果或宣称能正确回答绝大多数问题。

开发期间用旧0.6B模型检查了新流程：截图中的 Jev 问答能检索后生成，计算、统计、翻译、检索及停止分支可运行，但改写仍可能改变原事实，资料回答也可能出现超出证据的措辞。这些结果不能冒充1.7B的测量。1.7B实际输出和速度在安装后的本机评价记录中确认。

## 模型存放与恢复

新权重：`models/qwen3-1.7b`，原0.6B权重仍在`models/decision`。下载清单固定每个文件revision、大小和SHA256。下载不会更改正在使用的模型；文件全部校验完成后才安装配置并切换模型清单。

原代码和模型清单备份在 `.repair-backups/offline-v02-*`。下载失败可以重新执行升级命令续传。代码安装或基本推理验证失败时尝试恢复原代码与清单；新权重保留以便再次尝试。无需重新安装环境，无模型文件写入C盘。
